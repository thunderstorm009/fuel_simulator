# Sprint reporting
1. Read the sprint prompt, the diff since the last tag and test outputs.
2. Fill docs/templates/sprint-report.md into docs/sprint-reports/sprint-NN.md: behavior implemented, decisions and rejected alternatives, files, APIs, commands with real results, evidence paths, problems and root causes, not done, risks, next dependencies.
3. Update docs/PROGRESS.md: what exists now, tag to create, carried-over items, exact first task for the next sprint. This file is the next agent's memory.
4. Mark criteria passed only when verified; leave EVIDENCE: placeholders instead of inventing evidence.
5. Prepare the five-minute update: problem, change, live demo, evidence, gap and next step.
6. Stop for human review. Do not start the next sprint.
